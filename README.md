# MTL-ALIGNN: code, models, and supporting data

A compact package for reviewing the manuscript results, running model inference, and retraining experiments. Files were copied and selected from `D:\ck\two` and `D:\ck\two dft`. Both original directories remain unchanged.

## Directory structure

| Directory | Contents |
| --- | --- |
| `code/` | Data preparation, models, training, evaluation, plotting, and tests |
| `configs/` | Project and experiment configurations, including original configurations |
| `data/` | C2DB database, labels, fixed splits, and processed tables |
| `environment/` | Original environment notes and recorded installed versions |
| `licenses/` | Existing licensing status |
| `models/` | Best checkpoints for the final five-member MTL-ALIGNN ensemble, totaling 83.36 MB |
| `results/` | Predictions, metrics, and figures for main, baseline, ablation, OOD, review, and tuning experiments |
| `supplementary_data/` | DFT inputs and final outputs, unique manuscript materials, method notes, and provenance records |

The retained database, `data/c2db.db`, contains 16,905 records. The source data summary reports 8,102 supervised records and 8,803 Unknown candidates. Labels and existing prediction values have not been changed.

Their model weights must be regenerated by training with the corresponding configurations.

Figures in `results/paper/`, `results/paper_figures/`, and `results/figure6/` are retained. Unique revised figures, tables, and historical plotting code from the old manuscript bundle remain in `supplementary_data/paper/`. Removed duplicate inputs are mapped to retained copies in `supplementary_data/provenance/DUPLICATE_MAP.csv`. The historical bundle plotting script depends on its original layout; consult that mapping when locating inputs. Main plotting scripts are in `code/scripts/`.

## Running the package

The following examples use the existing local environment. On another machine, first configure a compatible environment using the records in `environment/`.

```powershell
cd D:\ck\MTL-ALIGNN
$PythonExe = 'D:\ck\anaconda_env\envs\two\python.exe'
& $PythonExe predict.py --dry-run
& $PythonExe train_fold.py --dry-run

# First inference run: regenerate Unknown-pool graphs from the retained database.
& $PythonExe predict.py --prepare-graphs

# First GNN training run: regenerate supervised graph caches.
& $PythonExe train_fold.py --prepare-graphs --seed 2025

# Tabular baseline training does not require graph caches.
& $PythonExe train_fold.py --experiment configs/experiments/main/M01_random_forest.yaml --backend tabular --seed 2025
```

Graph caches in `data/processed/graphs/` are reproducible generated files and are omitted from this compact package. `--dry-run` only reports inputs and missing caches. Actual inference or GNN training requires `--prepare-graphs` to generate missing caches explicitly. Later runs can reuse them. Cache generation and retraining increase the local directory size; these outputs are excluded by `.gitignore`.

`predict.py` screens the existing Unknown pool with the five-member ensemble. `train_fold.py` uses the existing fixed split and independent seeds; its filename follows the supplied example and does not indicate K-fold cross-validation. New outputs go to `results/reproduced/`. `code/package_runtime.py` relocates historical paths in memory. Retained scientific CSV files and experiment configurations keep their original values. Some historical PowerShell and plotting scripts contain machine-specific paths and require path checks before use.

## DFT materials

`supplementary_data/dft/materials_studio/` retains `.cell`, `.param`, structure files, `.castep`, `.phonon`, convergence tests, and other text outputs. The original input preparation code is in `supplementary_data/dft/input_preparation/`.

Large `.castep_bin` and `.cst_esp` files were removed. This directory supports inspection of existing results and new calculations from inputs; it does not contain all intermediate restart states. The full Materials Studio project remains in the unchanged source directory, `D:\ck\two dft`.

## Selection, language conversion, and verification

Non-final weights, graph caches, runtime logs, existing archives, compiled caches, editor settings, and temporary reference images were removed. Duplicate review and manuscript files were deleted only after confirming an identical retained copy by SHA-256. Unique figures and data were preserved.

All package filenames, documentation, and user-facing script messages are in English. Original external path identifiers are preserved losslessly using Unicode escapes where needed; external source directories were not renamed. In provenance CSV source-path fields and historical audit text, a sequence such as `\uXXXX` represents the original Unicode character. `LANGUAGE_PATH_MAP.json` records package path renames; its JSON escapes preserve the original names.

`supplementary_data/provenance/FILE_INDEX.csv` records retained source files and their current paths and hashes. `original_sha256` preserves the source hash when a document or script was translated. `DELETED_FILES.csv` records prior deletions and reasons; `DUPLICATE_MAP.csv` identifies retained equivalents. `MODEL_INDEX.csv` lists the final five checkpoints. `CHECKSUMS.sha256` and `PACKAGE_CHECKSUMS.sha256` describe the current package. `ENGLISH_CONVERSION_REPORT.json` records the language conversion and final checks. Earlier organization and cleanup reports describe their respective historical stages.

No full training run, whole-pool inference, or DFT calculation was performed during organization, cleanup, or translation. The original directories did not provide a project license. The current LICENSE records that status and does not assign an MIT or other open-source license.
